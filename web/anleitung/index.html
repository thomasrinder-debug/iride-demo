iRide Demo einrichten

Kickr-Anzeige mit Street View, Höhenprofil und Testmodus. Diese Seite zeigt live, was schon eingerichtet ist.

Server … Browser … Street View … Garmin … Kurse …

Der Server läuft nicht, die Seite ist nur als Datei geöffnet. Starte einrichten.cmd (Windows) bzw. einrichten.command (Mac), dann lädt sie sich mit Status neu: http://localhost:8765/anleitung/

1 Browser: Chrome …

iRide spricht per Web Bluetooth mit dem Kickr, und das gibt es nur in Chrome (oder Edge), auf Windows, macOS, Linux und Android. Firefox und Safari können es nicht.

iPad und iPhone: Bluefy statt Chrome

Chrome auf dem iPad läuft mit Apples Safari-Engine und hat deshalb kein Web Bluetooth: iRide und der Testmodus laufen, „Kickr verbinden“ aber nicht. Fürs iPad nimmst du Bluefy (App Store), einen Browser mit Web Bluetooth. Dafür braucht es HTTPS im WLAN: Server mit --lan starten, die CA einmal in Safari installieren und vertrauen, dann iRide in Bluefy öffnen (Anhang unten). Am iPad die automatische Sperre auf „Nie“ stellen.

Kein Chrome gefunden. Der Testmodus läuft auch in anderen Browsern, für den Kickr brauchst du Chrome: google.com/chrome.

Nur auf dem Mac

Beim ersten Verbinden fragt macOS, ob Chrome Bluetooth nutzen darf: erlauben. Wenn nicht gefragt wird oder du abgelehnt hast: Systemeinstellungen → Datenschutz & Sicherheit → Bluetooth, Chrome einschalten, Chrome neu starten.

Prüfpunkt: Diese Seite ist in Chrome offen, und oben steht „Browser: Chrome“.

2 Street View (Google, freiwillig) …

Ohne Schlüssel läuft alles außer dem Street-View-Bild: Karte, Höhenprofil, Werte und Testmodus gehen trotzdem. Für Street View brauchst du einen eigenen Schlüssel für die Maps JavaScript API. Das dauert etwa 10 Minuten.

  1. Projekt anlegen in der Google Cloud Console, Name z. B. iride.
  2. Abrechnungskonto mit dem Projekt verbinden. Google verlangt das auch für die kostenlose Nutzung; für eine private Kickr-Anzeige reicht normalerweise das monatliche Freikontingent. Die aktuellen Preise stehen bei Google.
  3. Maps JavaScript API aktivieren (Knopf „Aktivieren“).
  4. Anmeldedaten → „Anmeldedaten erstellen“ → „API-Schlüssel“.
  5. Den Schlüssel beschränken (Stift-Symbol beim Schlüssel):
    • Anwendungseinschränkung: Websites, Einträge http://localhost:8765/* und http://127.0.0.1:8765/* (mit --lan zusätzlich https://<IP>:8443/*).
    • API-Einschränkung: nur Maps JavaScript API.
  6. Empfohlen: Tageslimit setzen, z. B. 1000 Aufrufe pro Tag. Dann kann nichts aus dem Ruder laufen.
  7. Schlüssel hier einfügen und speichern. Er landet nur in lokal.py auf diesem Rechner, nie im Git.

Prüfpunkt: „Testen“ zeigt ein Street-View-Bild aus Alpe d'Huez, oben steht „Street View: OK“.

3 Garmin (freiwillig) …

Damit schickt iRide eine Strecke aus dem Katalog als Kurs an deinen Garmin Edge („Fahren“ im Katalog). Ohne Garmin fährst du die Strecken genauso in iRide.

  1. Ins Terminal-Fenster der Einrichtung wechseln und g eingeben (oder später: einrichten.cmd --garmin bzw. sh einrichten.sh --garmin).
  2. E-Mail, Passwort und, falls eingeschaltet, den MFA-Code eingeben. Nur im Terminal, nie auf einer Webseite.
  3. Gespeichert werden nur die Anmelde-Tokens in daten/garmin/, nie das Passwort. Abmelden: den Ordner löschen.

Die Bibliothek garminconnect ist inoffiziell. Ändert Garmin etwas, kann die Übertragung ausfallen; iRide selbst läuft weiter. Für die Übertragung muss ein Edge im Garmin-Konto aktiv sein.

Prüfpunkt: Oben steht „Garmin: verbunden“ mit deinem Namen. Im Terminal testet t die Anmeldung.

4 Los geht's: Testmodus ohne Kickr

Die fünf Demo-Kurse gehen von leicht bis Tour de France. Ein Klick lädt den Kurs und startet den Testmodus.

Im Testmodus

  • Der Regler in der Leiste stellt die simulierte Leistung ein (50–450 W), daneben der Zeitraffer (1× bis 60×).
  • Puls und Trittfrequenz werden grob nachgebildet; das Tempo folgt aus Leistung, Steigung und Masse (MASSE_SYSTEM in lokal.py).
  • „Katalog“ zeigt die fünf Strecken mit Karte und Profil, „Anleitung“ führt hierher zurück.
Prüfpunkt: Nach „Moselweinstraße“ zählt die Distanz hoch, und der Punkt auf dem Höhenprofil wandert.

5 Mit dem echten Kickr

  1. Kickr einschalten, Bluetooth am Rechner an. Die Wahoo-App darf nicht gleichzeitig verbunden sein.
  2. In iRide (Chrome) „Kickr verbinden“, in der Liste den Kickr wählen. Ebenso „HF verbinden“ für den Brustgurt.
  3. iRide liest Leistung, Tempo und Trittfrequenz vom Kickr und fährt damit den Kurs ab: Bild, Karte und Profil laufen mit.
Steigung am Kickr: iRide ist eine Anzeige und stellt den Widerstand des Kickr nicht selbst ein. Die Steigung kommt von einem Garmin Edge, der denselben Kurs fährt („Strecke folgen“, Kickr als Fahrradtrainer gekoppelt). Den Kurs schickt „In iRide fahren“ im Katalog an den Edge (Schritt 3). Dann in iRide „Scharf“ tippen, am Edge starten, lostreten; mit „Edge-km“ gleichst du die Distanz ab, falls sie abweicht. Ohne Edge rollt der Kickr mit seinem Grundwiderstand, iRide zeigt die Fahrt trotzdem an.

Automatisch verbinden beim nächsten Öffnen: In Chrome chrome://flags/#enable-web-bluetooth-new-permissions-backend und chrome://flags/#enable-experimental-web-platform-features einschalten. Ohne die Flags tippst du einmal pro Gerät auf „Alle verbinden“.

Prüfpunkt: Der Knopf zeigt „Kickr verbunden“, beim Treten erscheinen Watt und Tempo.

Wenn's hakt

  • „Port 8765 ist belegt“: Läuft iRide schon in einem anderen Fenster? Sonst mit anderem Port starten: start.cmd --http-port 18765. Dann gilt die Google-Beschränkung für den neuen Port.
  • Kein „Kickr verbinden“-Dialog: nicht Chrome/Edge, Bluetooth aus, oder (Mac) Chrome hat keine Bluetooth-Freigabe.
  • Street View bleibt grau: API nicht aktiviert, Abrechnung fehlt oder die Website-Beschränkung passt nicht zur Adresse. „Testen“ zeigt den Grund.
  • Python fehlt / zu alt: iRide braucht Python 3.12 oder neuer. macOS bringt nur 3.9 mit: python.org oder brew install python@3.13.
  • Mac: „kann nicht geöffnet werden“ beim Doppelklick auf .command: Rechtsklick → Öffnen, oder im Terminal sh einrichten.sh.
  • Neu anfangen: .venv, lokal.py und daten/ löschen, dann wieder einrichten. Außerhalb des Repo-Ordners wird nichts angelegt.
Anhang: Tablet im WLAN (HTTPS)

Ein Tablet erreicht den Rechner nicht über localhost, und Web Bluetooth braucht dann HTTPS. iRide bringt dafür eine eigene kleine Zertifizierungsstelle (CA) mit.

  1. Server mit start.cmd --lan bzw. sh start.sh --lan starten. Das Terminal zeigt die Adressen.
  2. Auf dem Tablet http://<IP>:8765/ca.crt öffnen und die CA installieren (iPad: Einstellungen → Allgemein → VPN und Geräteverwaltung, danach Info → Zertifikatsvertrauenseinstellungen einschalten).
  3. Dann https://<IP>:8443/ öffnen: Android in Chrome, iPad in Bluefy (nicht Chrome oder Safari, die haben auf iOS kein Web Bluetooth).

Auf dem Mac selbst braucht man das nicht. Soll ein Mac die CA trotzdem kennen: ca.crt aus _zertifikat/ per Doppelklick in den Schlüsselbund, dort „Immer vertrauen“.
